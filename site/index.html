Maintenance Manager for Envoy®

Flip a switch, your apps show a maintenance page. Flip it back, they're live. Their routes never notice.

A self-contained Helm chart that puts web apps behind maintenance pages, interstitials and banners on any Kubernetes® cluster running Envoy Gateway ≥ 1.8, without touching the apps or their HTTPRoutes.

  • Hands off your routes. It only reads HTTPRoutes, so it works where a platform owns and regenerates them.
  • Zero overhead at rest. No window armed, no extra hop: Envoy never calls it.
  • Fail-open. If it is down, slow or misconfigured, traffic flows as if it was never there.
  • Plays nice with platform auth. Its policy merges into Gateway-level SecurityPolicies instead of replacing them.
  • No database. State lives in three custom resources.

How it works

You describe three things, usually in the built-in editor:

  • a MaintenanceService: which HTTPRoutes make up an app (a label selector);
  • a MaintenancePage: what users see (your HTML template, or the built-in one, and texts per language);
  • a MaintenanceWindow: when, and what happens, as phases.
PhaseWhat users get
bannerThe app, plus a header it can show as a banner.
interstitialYour page once per session, then the app.
blockA 503 with your page, or application/problem+json for APIs, plus Retry-After.

Fifteen minutes before a window starts, it attaches one SecurityPolicy per app namespace to the matching routes, so Envoy asks it about every request. After the window, it removes it.

Install

Every release lists its chart and image digests, with these commands ready to paste. Check it was built here, then install it by digest:

gh attestation verify oci://ghcr.io/prosperity-solutions/charts/maintenance-manager@sha256:<chart digest> \
  --repo prosperity-solutions/maintenance-manager \
  --signer-workflow prosperity-solutions/maintenance-manager/.github/workflows/ci.yml \
  --source-ref refs/heads/main --deny-self-hosted-runners

helm install mm oci://ghcr.io/prosperity-solutions/charts/maintenance-manager@sha256:<chart digest> \
  -n maintenance-manager --create-namespace --set editor.password=<at least 12 characters>

Then open the editor NEW!

kubectl -n maintenance-manager port-forward svc/maintenance-manager 8080
# http://localhost:8080, user admin, the password from editor.password

A dashboard shows which windows are armed, which routes they cover, and whether Envoy accepted the policy. Start next phase now is one click.

Make the page yours

The built-in page is plain on purpose. Want your colours, your logo, your tone? Give the page an HTML template. It is a Go html/template, not Handlebars:

<h1>{{.Title}}</h1>
<p>{{.Message}}</p>
{{if .Until}}<p>Back at {{.Until}}</p>{{end}}
{{if .Interstitial}}<a href="">{{.Continue}}</a>{{end}}
  • Times in the visitor's own zone. {{.Until}} shows 23:30 MEZ on a German page in Berlin, 05:30 PM EST on an English one in New York.
  • The button speaks their language. {{.Continue}} is your text per language, or a built-in one (Weiter, Continuer, …).
  • Self-contained. CSS in a <style> tag, images inline: during a block, the app's own host serves nothing else.

Let an agent write it. The page guide has every rule, a full branded example, and a brief to paste into your coding agent. Then check it in the editor's preview.

Tell users in the app

A single file, no dependencies, under 4 KB gzipped. It shows a banner before maintenance, covers the page during a block, and reloads the tab when it ends:

<script src="/static/maintenance-manager.js" data-dismiss="click" defer></script>

Self-host it from the release assets. It works under a strict CSP and Trusted Types. Make it match your app with five CSS variables:

#maintenance-manager { --mm-bg: #c2410c; --mm-fg: #fff; --mm-accent: #fde68a;
  --mm-font: system-ui, sans-serif; }

Want it fully native? Skip the script: your app reads /__maintenance-manager/status (title, message, until, action) and draws its own banner. The app guide has both ways, the exact formats, and a brief for your coding agent.

Good to know

The 60-second drain

Attaching or removing a policy makes Envoy drain the listener: open connections close gracefully over 60 seconds and reconnect. That happens when a window arms and disarms, not during maintenance.

Letting your team through

Set a bypass token and send it as a header with a browser extension. No bypass links and no cookies, so the token never lands in URLs or logs.

If something breaks

Envoy lets traffic through. And a window can always be stopped from the command line:

kubectl -n maintenance-manager patch mmw <window> --type=merge -p '{"spec":{"enabled":false}}'

All the details are in the README.
